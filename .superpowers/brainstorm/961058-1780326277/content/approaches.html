Three approaches to building the app

Pick the one that fits where you are now and where you're going

A

Expo (Managed) — Recommended

React Native wrapped in Expo's toolchain. EAS Build produces the APK in the cloud — no Android Studio needed locally. Expo handles push notifications out of the box.

Pros

  • Fastest to get an APK in your hands
  • Push notifications with 5 lines of code
  • OTA updates — ship JS fixes without resubmitting to store
  • Easy path to iOS later

Cons

  • Slightly less control over native layer
  • EAS Build (free tier is slow ~15 min builds)
B

Bare React Native + Expo modules

Full React Native CLI with Expo libraries bolted on. Same notifications infrastructure, full native control.

Pros

  • Full control over native code
  • Still gets Expo's notification library

Cons

  • Need Android Studio to build locally
  • More setup and maintenance
  • Harder for future contributors to onboard
C

React Native CLI only (no Expo)

Pure React Native. Maximum flexibility, standard for large commercial teams.

Pros

  • No third-party build dependency
  • Full native access

Cons

  • Most setup work
  • Push notifications require more manual config (Firebase)
  • Overkill for this stage

Note on auth

The web UI uses cookie-based sessions. The mobile app will need a JWT token endpoint added to the FastAPI backend — standard for mobile clients, small addition to the existing API.
